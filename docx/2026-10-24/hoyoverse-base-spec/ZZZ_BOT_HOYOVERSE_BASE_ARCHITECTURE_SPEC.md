# 米家游戏通用底层依赖（HoYo-Base / Game-Profile）架构设计与独立仓库规划方案

- **方案提出时间**: `2026-10-24 22:45:00 +08:00`
- **核心定位**: 彻底拆解 TRSS-Yunzai 生态中“其他米家游戏插件强制依赖原神插件”的历史技术负债，构建独立的通用米游社社区与多游戏账户底层网关。
- **关联背景**: 结合 ZZZ-Bot 专精化改造及 NapCat 架构重构，彻底清除 `plugins/genshin` 与 `plugins/miao-plugin` 的业务指令污染。

---

## 一、 为什么您的理解“完全正确且直击痛点”？

### 1.1 历史倒错的成因（技术负债溯源）
在云崽（Yunzai-Bot）诞生初期（v1/v2 时代），它仅仅是一款原神（Genshin）QQ机器人。因此：
- 米游社扫码登录、米游社 Cookie/Token 存储、DS 动态签名计算、Takumi API 网关等**社区级通用能力**，被全部硬编码塞进了 `plugins/genshin` 插件内部；
- 后来崩坏：星穹铁道（HSR）和绝区零（ZZZ）上线，社区开发者开发 `StarRail-Plugin` 或 `ZZZ-Plugin` 时，由于底层没有独立的米游社通信库，**只能被迫 `import ... from '../../../genshin/model/...'`**；
- 这导致了一个荒谬的架构倒错：**想运行一个绝区零机器人，必须先安装一个完整的原神插件，甚至还要连带安装喵喵插件来满足原神基类的 `#miao` 模块依赖。**

### 1.2 新架构的破局点（领域职责正本清源）
您的构想完全符合**领域驱动设计（DDD）**与**接口隔离原则（ISP）**：
- **米游社/HoYoverse 是账号与社区网关**，负责管理通行证、Token、扫码、用户-角色映射；
- **具体游戏插件是业务消费方**，只负责对应游戏的玩法逻辑（圣遗物/驱动盘、深渊/式舆、抽卡、角色面板）。

二者本就该完全解耦！

## 三、 独立仓库的核心功能模块划分

独立仓库（例如 `trss-plugin-game-profile` 或 `yunzai-hoyoverse-base`）应包含以下四大核心模块：

### 1. 登录与凭据中心（Auth Module）
- **功能**：
  - 处理 `/扫码登录`、`/绑定CK`、`/刷新Token`、`/退出登录`；
  - 维持米游社登录二维码的生成、轮询、扫码确认、换取 `stoken_v2` / `ltoken_v2` / `mid`；
  - 自动管理设备指纹（Device FP），降低米游社风控概率。
- **纯净性**：**绝不携带任何游戏指令**（没有查圣遗物、没有原神深渊、没有抽卡统计）。

### 2. 角色与绑定关系中枢（Account Topology）
- **功能**：
  - 用户只要扫码成功一次，底层自动调用米游社接口，将其名下的**所有原神、星铁、绝区零、崩坏3 UID 一并识别入库**；
  - 提供标准的抽象类：
    ```typescript
    export interface IGameUser {
      getUid(game: 'zzz' | 'sr' | 'gs'): string;
      setUid(game: string, uid: string): Promise<boolean>;
      getCk(game?: string): Promise<UserCookie>;
      getAllRoles(): GameRole[];
    }
    ```
  - 提供轻量用户交互指令：`/绑定UID <游戏> <UID>`、`/我的UID`、`/切换UID`。

### 3. 米游社通信与网关（Client Gateway）
- **功能**：
  - 统一的 `MiyousheClient`，所有游戏插件继承或注入该客户端即可自动获得合规的请求签名（DS）、防重放时间戳与 Headers；
  - 统一错误码分流（如遇到 1034 验证码时触发全局统一的风控事件提醒，而不是每个游戏各自崩溃）。

### 4. 垫片与生态兼容层（Shim Layer）
- **功能**：
  - 为了兼容现有无需修改源码的 `ZZZ-Plugin`，仓库打包或安装后，在 `plugins/genshin/model/` 放置 3 个极简代理文件：
    - `NoteUser.js -> export { NoteUser as default } from 'game-profile'`
    - `mysApi.js -> export { MysApi as default } from 'game-profile'`
    - `user.js -> export { User as default } from 'game-profile'`
  - **收益**：既能独立作为一个全新通用标准发布，又能直接平替老系统，做到 100% 零修改兼容。

## 四、 实施路径与开发计划

建议将该目标拆分为以下清晰的实施阶段：

1. **第一阶段：独立仓库原型搭建（提取通用层）**
   - 新建独立 Git 仓库（如 `game-profile`）；
   - 从成熟实现中提炼出纯粹的 `DS.js`、`MiyousheApi.js`、`NoteUser.js` 和 SQLite 模型；
   - 编写自动化单元测试，验证扫码流程模拟与签名算法正确性。
2. **第二阶段：接入与平替验证（在 ZZZ-Bot 容器内实测）**
   - 将 `game-profile` 挂载或注入测试容器；
   - 移出原版 `plugins/genshin` 与 `plugins/miao-plugin`，换上极简 Shim 垫片；
   - 验证绝区零便签（`%便签`）、面板（`%面板`）、签到（`%签到`）等所有核心功能无缝运行。
3. **第三阶段：开源与标准化**
   - 编写标准的 README 与开发接入指南，供其他想要脱离原神插件的开发者（如纯星铁 Bot、纯绝区零 Bot）直接使用。
