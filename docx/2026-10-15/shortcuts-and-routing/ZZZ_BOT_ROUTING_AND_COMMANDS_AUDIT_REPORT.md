## 1. “/帮助”路由偏折至原神喵喵帮助的根因诊断

### 1.1 实时日志还原与执行时序

从容器实时日志（`docker logs zzz-bot`）中抓取到的真实交互记录如下：

### 1.2 路由偏折全链路机理剖析

1. **输入阶段（QQ 客户端 -> TRSS-Yunzai 内核）**：
   - 用户在 QQ 群点击或输入斜杠快捷指令 `/帮助`。
   - TRSS-Yunzai `lib/plugins/loader.js` 的 `dealText(e)` 处理过程中，检测到行首以 `/` 或 `／` 开头，按照云崽标准将其改写为 `#` 前缀：
     `e.msg = e.msg.replace(/^[/／]/, "#")`
   - 此时消息内容被重写为 `e.msg = "#帮助"`。

2. **前置拦截阶段（`zzzShortcuts.js`，优先级 -1000）**：
   - 审查 `plugins/example/zzzShortcuts.js` 的 `accept(e)`：
     - 规则涵盖了抽卡（`抽卡分析`等）、便签（`体力`等）、面板（`面板`、`更新面板`等）、UID（`uid`）、绑定（`绑定`）以及签到（`签到`、`自动签到`等）。
     - **完全遗漏了“帮助”相关的所有规则**（既无 `/帮助`，也无 `帮助`、`/help`、`菜单` 等）。
   - `zzzShortcuts.js` 未能匹配到规则，直接返回 `false`，未能将 `e.msg` 重定向为绝区零专属帮助指令，消息原样流向后续普通插件。

3. **插件管道匹配阶段（优先级竞态与正则冲突）**：
   - 全容器内仅存在两个注册 `help` 的插件：
     - `miao-plugin/apps/help.js`
     - `ZZZ-Plugin/dist/apps/help.js`
   - **`miao-plugin` 的规则定义**：
     ```javascript
     rule: /^(\/|#)?(喵喵)?(命令|帮助|菜单|help|说明|功能|指令|使用说明)$/
     ```
     该正则直接匹配任意无前缀或带有 `#/` 前缀的 `帮助`、`命令`、`help` 等。
   - **`ZZZ-Plugin` 的规则定义**：
     ```javascript
     reg: `${rulePrefix}(帮助|help)$`
     // 其中 rulePrefix = '^((#|%|/)?(zzz|ZZZ|绝区零))'
     ```
     ZZZ-Plugin 原生**只接受带有 `zzz` 或 `绝区零` 标识的前缀**（如 `#绝区零帮助`、`%zzz帮助`、`zzz帮助`、`/绝区零帮助` 等），**无法匹配**不带命名空间的孤立 `#帮助` 或 `/帮助`。
   - 结果：`miao-plugin` 抢先捕获 `#帮助`，调用 `Help.render()` 生成并输出了原神帮助长图（`miao-plugin/help/index`）。

## 2. 前置路由与系统交互其他潜在问题审查

除了“/帮助”外，通过结合代码静态分析与运行时日志，还排查出以下三项深层缺陷：

### 2.1 原神 `miao-plugin` 对绝区零角色的前置“假命中与穿透延迟”

在日志中观察到如下现象：
```log
[15:17:30.641][INFO] ... [#面板 蕾米] [喵喵:角色面板(profileDetail)] [开始处理]
[15:17:30.643][INFO] ... [#面板 蕾米] [[ZZZ-Plugin]Panel(handleRule)] [开始处理]
```
- **成因**：`miao-plugin/apps/profile.js` 的正则极其宽泛：
  `^#*([^#]+)\s*(详细|详情|面板|面版|圣遗物|遗器|武器[1-7]?|伤害([1-9]+\d*)?)...`
  当 `zzzShortcuts.js` 把 `/面板 蕾米` 改写为 `#绝区零蕾米面板` 时，喵喵的正则依然能匹配并提取出角色名 `绝区零蕾米`。随后喵喵进入 `ProfileDetail.detail()`，尝试在原神/星铁库中查找该角色，查找失败后才 `return false`，由 loader 交给下一个插件 ZZZ-Plugin 处理。
- **潜在隐患**：
  1. 增加了消息处理链路的无谓开销。
  2. 若未来绝区零角色名、别名或拼音与原神/星铁角色或武器别名产生重合，喵喵会判定为“原神角色”，截断流水线并报错“暂无该角色面板”，导致绝区零面板彻底无法查询。

### 2.2 核心战绩与玩法指令在快捷指令中的大面积盲区（深渊/强袭战/爬塔等）

当前 `zzzShortcuts.js` 仅映射了 6 个功能大类，对于绝区零高频核心战绩功能存在严重缺失：
1. **`/深渊`、`/式舆`、`/式舆防卫战`**：
   - 缺少快捷映射。
   - 经内核转换为 `#深渊` 后，会直接命中 `plugins/genshin/apps/role.js`（原神深境螺旋查询指令 `^#[上期|往期|本期]*(深渊|深境|深境螺旋)...`）。用户在绝区零群点击快捷指令 `/深渊`，会被错误当作原神深渊处理，导致提示原神绑定或报错。
2. **`/强袭战`、`/危局强袭战`、`/拟境`、`/临界推演`、`/爬塔`、`/零号空洞`**：
   - 缺少快捷映射。
   - 内核转换为 `#强袭战`、`#爬塔` 等。因 ZZZ-Plugin 原生严格要求带 `rulePrefix`（必须含 `zzz`、`绝区零` 或 `%`），而没有任何其他插件注册这些纯词，导致用户在 QQ 群发送 `/强袭战` 时**没有任何响应（石沉大海）**。
3. **`/月报`、`/日历`、`/兑换码`、`/攻略`、`/卡池`**：
   - 同样因为缺失斜杠映射，用户直接点击快捷指令均无法唤起绝区零对应功能。

### 2.3 Telegram 实例冲突（409 Conflict）与 QQBot 偶尔连接过期（4009）

在容器 stderr/stdout 日志中发现：
```log
body: {
  ok: false,
  error_code: 409,
  description: 'Conflict: terminated by other getUpdates request; make sure that only one bot instance is running'
}
[ERRO] [CLIENT] 发生错误：4009 连接过期，请重连
```
- **Telegram 409 冲突**：说明当前部署的 Telegram Bot Token 正被另一个正在运行的外部实例或残留进程同时拉取（`getUpdates` 互斥），导致 Telegram 轮询被对端抢占而反复断开。
- **QQBot 4009 连接过期**：官方 Bot 长连接凭证短期过期，虽底层具备自动重连机制（1次重连即可恢复），但反映出网络波动或凭据刷新的正常生命周期事件。

## 4. 调研结论与后续架构建议

### 4.1 核心结论
1. **“/帮助”问题定位明确**：
   - 根因不在 TRSS-Yunzai 或 ZZZ-Plugin 本身，而是前置路由 `zzzShortcuts.js` 缺少对“帮助”的拦截映射，加之 `ZZZ-Plugin` 原生要求 `rulePrefix`（必须含 `zzz`/`绝区零`），导致裸指令 `#帮助` 被 `miao-plugin` 的通用捕获正则劫持。
2. **战绩核心模块具备完整支撑能力**：
   - ZZZ-Plugin 本身对**式舆防卫战（深渊）、危局强袭战、拟境湮灭战、临界推演、拟真鏖战试炼（爬塔）、零号空洞、迷宫诡域（绝科夫）**等所有游戏内高难与常驻玩法均具备高度成熟的代码实现和数据渲染能力。
   - 只要补全前置路由映射，即可在 QQ 快捷指令（斜杠 `/`）下 100% 正常调用。

### 4.2 后续演进建议（待授权后实施）

1. **补全 `zzzShortcuts.js` 基础帮助映射**：
   - 将 `^${P}(帮助|help|菜单|功能|指令)$` 统一映射为 `#绝区零帮助`，彻底截断喵喵原神帮助的抢占。
2. **扩充核心战斗与玩法快捷指令库**：
   - **深渊/防卫战**：`^${P}(上期|往期)?(式舆防卫战|式舆|深渊|防卫战)$` -> `#绝区零$1$2`（避免被原神深渊捕获）。
   - **强袭战**：`^${P}(上期|往期)?(危局强袭战|危局|强袭|强袭战)$` -> `#绝区零$1$2`。
   - **高难玩法**：拟境、推演、爬塔、零号空洞、迷宫诡域等一并纳入白名单。
   - **日历/月报/攻略**：`^${P}(日历|活动日历)$` -> `#绝区零日历`；`^${P}(月报|菲林|邦布券)$` -> `#绝区零$1`。
3. **消除单角色面板与喵喵插件的潜在正则冲突**：
   - 在 `zzzShortcuts.js` 处理单角色面板时，通过设置 `e.game = 'zzz'` 并在必要时阻断非绝区零插件的无谓穿透。
4. **清理 Telegram 多实例互斥**：
